# Управление сайтом External

Laravel 12 + Filament 5. Рабочая панель: `https://cw704626.tw1.ru/admin`. Содержание, база и ключ подписи хранятся вне публичной папки. Основной сайт `https://externlangschool.ru/` получает опубликованные HTML-страницы через HTTPS; оформление, URL, фотографии и метаданные сохранены.

## Что редактируется

- «Страницы»: 9 существующих страниц, включая документы, с блоками в порядке сайта.
- «Языки»: 7 языковых страниц.
- «Общие блоки»: меню, нижняя часть сайта, блок знакомства и форма.
- «Фотографии»: загрузка JPG, PNG и WebP, понятные названия и миниатюры.
- «Стоимость и расписание»: цена часа, автоматический пересчёт пакетов 4 × 4 и время занятий на всех страницах.
- Название и описание для поиска — в конце редактора каждой страницы.

Системные ключи, маршруты и шаблоны скрыты. Сохранение создаёт черновик. «Сохранить и посмотреть» сохраняет поля и открывает закрытый предпросмотр. «Опубликовать» требует явного подтверждения. Предыдущая опубликованная версия сохраняется в истории; восстановление возвращает её в черновик.

Редактор меняет содержание существующей структуры. Для добавления новой структуры блока, языка, страницы или новой логики формы нужен разработчик. Загрузка изображения сама по себе не публикует его. Заявки сохраняются в отдельном разделе панели и отправляются на почту школы.

## Заявки и почта

Основной сайт отправляет JSON по HTTPS на `/api/applications` домена CMS. Форма включается только при `APPLICATIONS_ENABLED=true` и настроенном `APPLICATIONS_ENDPOINT`. Получатель хранится в приватной `.env`, а не в HTML/JS. В production нельзя использовать фиктивные почтовые драйверы `log` или `array`.

Проверяются обязательные поля, телефон, список языков, длина комментария и отдельное согласие. Ограничены источники CORS, частота запросов; есть скрытое антиспам-поле и подписанный одноразовый идентификатор формы. Повтор с тем же идентификатором возвращает прежнюю заявку и не отправляет второе письмо. Согласие фиксируется с датой и снимком опубликованных текстов документов. Контакты и комментарии не записываются в технические логи.

Заявка сохраняется до отправки письма. `notified_at` означает, что почтовый транспорт принял уведомление, а не подтверждает доставку получателю. При ошибке транспорта письмо можно повторить из списка заявок; команда `applications:notify` также повторяет неудачные уведомления с интервалом не менее 15 минут, до пяти попыток. Записи с заполненным `notified_at` автоматически не повторяются.

На Timeweb с 22.10.2026 используется SMTP `smtp.timeweb.ru:465` с TLS и отправителем `notifications@externlangschool.ru`. Пароль хранится только в приватной серверной `.env`; получатель заявок задаётся отдельно через `APPLICATIONS_RECIPIENT`. В DNS Beget добавлены ключ Timeweb `dkim._domainkey`, DMARC `v=DMARC1; p=none` и SPF `v=spf1 include:_spf.timeweb.ru redirect=beget.com`. NS, MX и адреса сайта сохранены. SMTP-тест 22.10.2026 подтверждён владельцем в папке «Входящие» Gmail. Доставка прежних тестов на Яндекс не подтверждена; исходный тест через sendmail был получен в Gmail в папке «Спам».

Для перехода на SMTP скопируйте `deploy/configure-smtp.php` в приватный корень Laravel и положите пароль ящика отправителя в файл `storage/app/private/smtp-password.txt` с правами `0600`. Запустите `php configure-smtp.php storage/app/private/smtp-password.txt`. Скрипт сначала проверяет TLS и авторизацию на `smtp.timeweb.ru:465`, затем создаёт приватную резервную копию `.env`, переключает транспорт и очищает кеш конфигурации. Получатель заявок остаётся прежним. Временный файл пароля удаляется; при ошибке после изменения конфигурации восстанавливается исходная `.env`. Скрипт сам не отправляет тестовые письма. Публичные SPF/DKIM/DMARC нужно отдельно настроить у держателя DNS домена.

`deploy/enable-applications.php` предназначен только для первоначальной установки и настраивает старый транспорт sendmail. Не запускайте его повторно на работающем SMTP: он перезапишет почтовые настройки. Все установщики выполняются только из приватного корня Laravel и не должны попадать в `public_html`.

В панели Timeweb «Crontab» настроены повторная доставка раз в пять минут и ежедневная очистка базы командой `applications:prune`. Очистка удаляет обращения старше 180 дней, как указано в текущей политике. Удаление копий писем из Яндекс Почты и обработка запросов на отзыв остаются у владельца школы. Редактировать cron через SSH на этом аккаунте Timeweb нельзя — используйте панель.

`deploy/update-application-copy.php` вместе с `deploy/application-copy.json` заменяет старые сообщения об отключённой форме в правовых страницах. Он сохраняет историю публикаций и не публикует чужие черновики. Полные сведения о владельце школы пока не предоставлены: не выдумывайте реквизиты и не публикуйте приватную почту получателя в качестве контактной без согласования.

## Локальный запуск

Требуется PHP 8.2+, Composer и расширения `pdo_sqlite`, `mbstring`, `intl`, `dom`, `fileinfo`, `gd`, `openssl`; для получения публикаций основному сайту нужен `curl`. Зависимости зафиксированы под PHP 8.2.29. Node для стандартного интерфейса Filament не нужен.

```sh
cd cms
composer install
cp .env.example .env
php artisan key:generate
php artisan migrate
php artisan filament:assets
php artisan site:import --source=..
php artisan site:administrator
php artisan serve --host=127.0.0.1 --port=8008
```

Перед запуском скопируйте готовые HTML/CSS/JS, favicon и `assets` из корня репозитория в `cms/public`. Сгенерированные публичные копии исключены из Git. `site:import` выполняется один раз и отказывается затирать существующее содержание. Пароль `site:administrator` вводится скрыто; демонстрационного пароля в коде нет.

```sh
php artisan test
php artisan site:build
```

`site:build` пересобирает только опубликованные версии. Не используйте его как резервное копирование базы.

## Timeweb

### Два отдельных домена — текущая рабочая схема

Основной домен остаётся на основном проекте (`~/public_html`), админка — на техническом домене и проекте `external`. DNS и регистрация основного домена остаются в Beget. Привязывать основной домен к `external` не требуется. Изоляция обоих проектов включена; постоянный SSH для работы панели не нужен.

`/published-site` отдаёт только опубликованные страницы в подписанном JSON-пакете. Черновики, аккаунты, схема редактора и приватные настройки в него не входят. RSA-подпись SHA-256 создаётся приватным ключом CMS. Основному сайту передаётся только открытый ключ. На основном сайте нет HTTP-метода записи файлов и нет пароля хостинга.

`deploy/main-site/PublishedSiteGateway.php` проверяет TLS, подпись, домен, список 16 страниц, размер и время пакета. Он обновляет общую локальную копию максимум раз в 15 секунд и продолжает отдавать последнюю проверенную версию при сбое CMS. Если копии ещё нет, используются исходные HTML из `public_html/cms-publishing/fallback`. Загруженные фотографии имеют неизменяемые случайные имена и отдаются с домена CMS.

На Timeweb существующие `.html` могут отдаваться Nginx в обход правил Apache. Поэтому исходные 16 файлов и старый `index.htm` перенесены в резервную папку, а в корне работает PHP-обработчик. Нельзя возвращать статическую сборку в этот корень: она снова обойдёт публикацию из CMS.

```text
public_html/
  index.php, cms-site.php, .htaccess
  cms-publishing/        обработчик, открытый ключ и исходные HTML/fallback
  cms-cache/             последняя проверенная публикация; не источник содержания
  assets/, CSS, JS, favicon, robots.txt, sitemap.xml
external/
  ele-cms/               Laravel, .env, SQLite, storage, приватный ключ
  public_html/           вход в админку, ресурсы Filament и uploads
```

Настройки CMS: `APP_URL=https://cw704626.tw1.ru`, `CMS_SEPARATE_DOMAIN=true`, `CMS_SITE_URL=https://externlangschool.ru`, `CMS_MEDIA_URL=https://cw704626.tw1.ru`. Приватный ключ — `storage/app/private/publishing-private.pem`, права 0600. Создать его один раз, не заменяя рабочий:

```sh
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out storage/app/private/publishing-private.pem
chmod 600 storage/app/private/publishing-private.pem
openssl pkey -in storage/app/private/publishing-private.pem -pubout
```

Открытый ключ вставляется в `public_html/cms-publishing/config.php` по образцу `deploy/main-site/config.example.php`. Туда же копируются шлюз и PHP-обработчик. Правила из `rewrite-rules.txt` добавляются после существующих канонических перенаправлений. `DirectoryIndex` должен указывать на `index.php`.

`deploy/connect-domains.php` копируется в приватный корень Laravel как `connect-domains.php`. После подготовки обработчиков он проверяет реальный HTTPS-пакет и его подпись, переносит исходные HTML, сохраняет конфигурацию и настраивает домены в `.env`:

```sh
/opt/php82/bin/php external/ele-cms/connect-domains.php /home/c/cw704626/public_html
/opt/php82/bin/php external/ele-cms/artisan config:clear
/opt/php82/bin/php external/ele-cms/artisan site:setup-link
```

Перед запуском нужен корректный открытый ключ и существующие исходные страницы; перенос сначала проверяют на копии. Приватная резервная копия находится в `storage/app/private/domain-connection-*`. Для возврата к статической схеме восстановить HTML из `cms-publishing/fallback` и прежний `.htaccess` с `DirectoryIndex index.html`. Удалять приватную CMS или базу для отката не требуется.

Проверка передачи: запрос страницы основного сайта возвращает `X-External-Source: signed`; хеш `X-External-Publication` соответствует её опубликованному HTML. Вход в админку и предпросмотр закрыты от индексации. Основные `robots.txt`, favicon и sitemap обслуживаются основным доменом.

### Первичная установка Laravel

Структура аккаунта:

```text
external/
  ele-cms/               приватный Laravel, vendor, .env, SQLite, история
  public_html/           готовый сайт, index.php, ресурсы Filament, uploads
```

Нельзя размещать целый проект Laravel или его архив в `public_html`. `deploy/package.py` собирает архив с этой структурой, без локальных `.env`, аккаунтов, базы, загруженных пробных фото и журналов. Перед установкой сохраните копию текущего `public_html` вне публичной папки.

```sh
python3 cms/deploy/package.py /tmp/ele-cms-production.zip
```

В Timeweb сначала создайте сайт с директорией `external`, чтобы приватный Laravel и `public_html` находились внутри одного корня изоляции. Загрузите и распакуйте архив внутри `external`. Размещение приватных файлов рядом с основным `~/public_html` блокируется изоляцией Timeweb. После распаковки выполните из приватной `external/ele-cms` подходящим PHP CLI:

```sh
/opt/php82/bin/php install.php
```

Установщик проверяет расширения, создаёт приватную SQLite-базу и `.env` с правами 0600, генерирует ключ, применяет миграции, импортирует текущий сайт, публикует ресурсы и строит страницы. Повторная установка с существующим `.env` останавливается. Обычный `composer install --no-dev --optimize-autoloader` можно использовать вместо загрузки готового `vendor`.

В конце установщик выводит одноразовую ссылку первого входа, действующую 24 часа. Владелец сам задаёт почту и пароль. После первого администратора ссылка закрывается. Обновить ещё не использованную ссылку: `php artisan site:setup-link`. Не храните эту ссылку в Git и публичной переписке.

Параметры production: `APP_ENV=production`, `APP_DEBUG=false`, HTTPS `APP_URL`, `SESSION_SECURE_COOKIE=true`, абсолютные `DB_DATABASE` и `CMS_PUBLIC_PATH`. PHP-FPM должен иметь запись в `storage`, `bootstrap/cache`, SQLite и опубликованные HTML. Не используйте права 0777. После любых изменений `.env`: `php artisan config:clear`. Не включайте SPA без отдельной проверки сохранения черновиков.

## Сохранность и обновления

После начала работы клиентки база является основным источником опубликованного содержания. Не загружайте поверх её страниц результаты старой Python-сборки. Git хранит код; актуальные тексты, медиа, аккаунт и история находятся в базе и папке загрузок хостинга.

Резервируйте вместе `database/database.sqlite`, `.env` с ключом, `storage/app/private/publications` и `public_html/uploads`. Во время копирования базы используйте SQLite backup API или короткий режим обслуживания. Копии HTML перед публикацией находятся в приватной `storage/app/private/publications`; предыдущие данные доступны через историю в панели. Штатные резервные копии Timeweb дополняют эти копии.

При обновлении кода сохраняйте `.env`, базу, storage и uploads. Затем `composer install --no-dev --optimize-autoloader`, `php artisan migrate --force`, `php artisan filament:assets`, `php artisan optimize:clear`. `site:import` повторно не запускайте. Для восстановления администратору доступна команда `site:administrator`; аккаунты и регистрация публично не открыты.

Загружаемые изображения проходят проверку MIME, размера и разрешения, переупаковываются в WebP со случайным именем. SVG и исполняемые файлы не принимаются. Черновики закрыты авторизацией, не индексируются и не кешируются. Публикации защищены блокировкой и проверкой версии от перезаписи из старого окна.
